# Team Frontress Recruiting Bot

Отдельный сервис набора русскоязычных тестеров: Telegram-бот, адаптивный Mini App, Steam OpenID, выдача ключей и администрирование. Не зависит от игрового координатора и не запускает игровые серверы. Никакой американской рекламной кампании или определения гражданства здесь нет: язык и контент ориентированы на российскую аудиторию.

## Возможности

- Русский интерфейс в стиле Telegram, светлая/тёмная темы, графическая схема кампании RED/BLU. Схема явно помечена как концепт, не живые данные.
- Проверка подписи Telegram Mini App на сервере и вход через настоящий Steam OpenID. Пароли Steam сервис не получает; Steam Web API key не нужен.
- Постоянная связь одного Telegram ID с одним Steam ID. Оба идентификатора уникальны: смена Telegram не позволяет повторно использовать тот же Steam. Это защита от повторной выдачи аккаунтам, не доказательство уникальности человека.
- Автоматическая выдача заранее загруженного ключа при успешной привязке Steam. Транзакции SQLite защищают от параллельной выдачи одного ключа нескольким участникам. Повторный вход и `/key` возвращают прежний ключ.
- При исчерпании запаса участник остаётся зарегистрированным без ключа. После импорта нового запаса получение доступно через `/key`, повторный вход или кнопку проверки. Это не FIFO-очередь и не автоматическая раздача всем ожидающим.
- Лента объявлений и сохраняемая очередь личных сообщений с повторами, паузой при Telegram 429 и обработкой блокировки бота.
- Админка по списку Telegram ID: импорт ключей, статистика, список участников, публикация объявлений. Ключи участников в административном списке не показываются.
- Приглашения в существующую группу с автоматической проверкой и одобрением заявки зарегистрированного тестера со Steam и ключом.

## Ограничения Telegram

Bot API не умеет создавать группы или без согласия добавлять в них произвольных пользователей. Организатор создаёт закрытую супергруппу вручную и назначает бота администратором с правом приглашать участников. Сервис создаёт приглашение на один час с запросом на вступление; пользователь нажимает кнопку, а бот одобряет заявку после проверки. Заявки без подтверждённого Steam и выданного ключа отклоняются. Используйте отдельную группу тестеров, а не общую группу проекта с другими правилами вступления.

Бот может писать только пользователям, которые начали с ним личный диалог. Поэтому рекомендуемый первый шаг: `/start`, затем кнопка приложения. Открытие Mini App напрямую не гарантирует возможность личной рассылки; лента при этом доступна. Объявления отправляются в личные сообщения, а не в группу. Доставка как минимум однократная: при аварии после принятия сообщения Telegram возможен дубль.

## Подготовка

1. Создайте бота через `@BotFather` и получите токен. Укажите русские название, описание и команды `start`, `help`, `key`, `group`.
2. Подготовьте домен с HTTPS и сервер с доступом к `api.telegram.org` и `steamcommunity.com`. `PUBLIC_URL` должен быть точным HTTPS-origin без пути, query и завершающего маршрута.
3. Настройте Web App/Menu Button в BotFather на этот URL. `/start` также присылает кнопку открытия Mini App, поэтому menu button не обязателен.
4. Укажите числовые Telegram ID администраторов в `ADMIN_TELEGRAM_IDS` через запятую. Никнеймы не подходят. Проверяйте ID доверенным способом; если список пуст, админки ни у кого нет.
5. При необходимости создайте группу, добавьте бота и задайте её отрицательный ID в `TESTERS_CHAT_ID` (обычно `-100...`). Пустое значение отключает вступление в группу.
6. Подготовьте настоящие ключи доступа. Сервис не создаёт Steam-ключи и не проверяет их активацию. Ключи нужного приложения/пакета необходимо получить самостоятельно через разрешённые механизмы Steamworks либо вашей системы доступа.

## Запуск Docker

Команды выполняются из `services/recruiting-bot`. Создайте локальный `.env` по `.env.example` и заполните секреты; `.env` исключён из Git и Docker build context.

```sh
docker compose up -d --build
docker compose logs -f recruiting-bot
curl --fail http://127.0.0.1:8080/healthz
```

Сервис слушает только loopback хоста. Например, Caddy на хосте может завершать TLS:

```caddyfile
testers.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Замените пример домена своим. Внешний трафик направляйте на HTTPS-прокси, не на порт 8080. Не включайте логирование query string и заголовков авторизации: одноразовый Steam handoff содержит секретный ticket. Настройте ограничение частоты запросов на прокси перед публичным запуском.

Один экземпляр сервиса на один токен и одну SQLite-базу. При старте сервис удаляет установленный webhook, сохраняя ожидающие updates, и начинает long polling. Не используйте этот токен параллельно с другим бот-сервисом. Том `recruiting-data` переживает пересоздание контейнера; `docker compose down -v` удалит участников и запас ключей, так делать нельзя.

## Запуск Без Docker

Требуются Go 1.24+ и HTTPS reverse proxy. UI встраивается в бинарник, npm-сборка не требуется.

```sh
go build -o recruiting-bot .
```

Перед запуском задайте переменные окружения из таблицы. Сам бинарник `.env` не читает; файл автоматически обрабатывается только Docker Compose. Каталог БД должен существовать и быть доступен для записи.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен бота |
| `PUBLIC_URL` | Обязательный HTTPS-origin, например `https://testers.example.com` |
| `ADMIN_TELEGRAM_IDS` | Числовые ID через запятую; по умолчанию администраторов нет |
| `TESTERS_CHAT_ID` | Отрицательный ID существующей группы; необязательно |
| `DATABASE_PATH` | По умолчанию `recruiting-bot.db`; в Compose `/data/recruiting-bot.db` |
| `LISTEN_ADDR` | По умолчанию `:8080`; вне контейнера желательно `127.0.0.1:8080` |

## Первый Набор

1. Администратор отправляет `/start` и открывает приложение. Для админки привязывать Steam не требуется.
2. Внизу страницы импортирует ключи, по одному на строку. Пустые строки и точные повторы пропускаются.
3. Тестер отправляет `/start`, открывает приложение и выбирает Steam. Во внешнем браузере подтверждает показанный Telegram ID, затем входит в Steam. Ссылку входа нельзя пересылать: она одноразовая, действует десять минут и привязана к исходному Telegram.
4. После callback ключ автоматически закрепляется за тестером при наличии запаса. Он виден в браузере, в Mini App после обновления и по `/key`.
5. Тестер нажимает «Вступить в группу» либо `/group` и отправляет заявку. Бот одобряет её автоматически при корректных правах.
6. Администратор публикует объявление с инструкциями по активации, установке и ближайшей сессии. Сервис не придумывает инструкции для неизвестного пакета Steam.

## Безопасность И Данные

Telegram `initData` проверяется HMAC, срок свежести один час. Сессии действуют 30 дней; в SQLite хранится хеш случайного токена. В обычном браузере используется `HttpOnly; Secure; SameSite=Lax` cookie. В Telegram Mini App дополнительно используется Bearer-токен только в памяти страницы, чтобы работать и при блокировке сторонних cookie в Telegram Web; он не сохраняется в localStorage. Steam использует отдельный browser cookie, подписанный ответ провайдера, одноразовые state/nonce и проверку `return_to`. POST-запросы ограничены проверкой Origin, административные права проверяются на сервере.

База содержит Telegram ID, имя, Steam ID, выданные ключи, объявления и статусы доставки. Ключи хранятся в открытом виде, поэтому ограничьте доступ к диску, `.env` и резервным копиям, используйте шифрование диска/бэкапов. Не публикуйте БД и не прикладывайте её к баг-репортам. Для консистентной резервной копии используйте SQLite online backup либо остановите сервис и сохраните весь каталог БД, включая WAL/SHM, если они остались. Проверяйте восстановление отдельно. Потеря базы может привести к повторной раздаче ключей при импорте старого списка.

Перед публичным российским набором организатору нужно определить оператора данных, политику обработки/сроки хранения, порядок отзыва согласия и удаления, подходящее размещение данных и применимость требований 152-ФЗ. Краткое уведомление в UI не заменяет юридическую политику. Автоматическое удаление и перенос привязки пока не реализованы: удаление связи без сохранения учёта выдачи позволит повторный запрос ключа. Проверку возраста, гражданства, владения TF2 и активации ключа сервис не выполняет.

## Проверки

```sh
go test ./...
go test -race ./...
go vet ./...
node --check web/app.js
```

Тесты используют временные SQLite-базы и подменённые ответы Telegram/Steam. Покрываются конкурентная выдача, уникальность связок, подписи, повторы входа, browser handoff, Bearer без cookie, CSRF, админские права, заявки в группу, очередь и перезапуск. Перед набором необходим живой smoke-test с реальным ботом и Steam на Telegram Android/iOS/Desktop/Web: это не заменяется unit-тестами.

## Следующие Этапы

1. Политика данных и явное согласие, `/stop` и `/resume`, удаление/экспорт данных с сохранением безопасного учёта выдачи, журнал административных действий.
2. Анкета тестера: часовой пояс, доступное время, железо, опыт; волны приглашений и автоматическое FIFO-распределение нового запаса с уведомлением.
3. Расписание сессий по МСК, RSVP, напоминания, правила группы и структурированные баг-репорты с вложениями.
4. Антиабуз и эксплуатация: лимиты, метрики очереди и запаса ключей, оповещения, роли админов, сегменты рассылок, управление неудачными отправками, проверка восстановления резервных копий.
5. После первых русскоязычных тестов: отдельная англоязычная воронка через Steam, аналитика источников и локализация без смешивания аудиторий.
